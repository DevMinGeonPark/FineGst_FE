## User Scenarios & Testing *(mandatory)*

### User Story 1 - OTA 업데이트 자동 수신 (Priority: P1)

사용자가 앱을 실행할 때, 새로운 JavaScript 번들 업데이트가 있으면 백그라운드에서 자동으로 다운로드하고 다음 앱 실행 시 적용한다. 이를 통해 사용자는 앱스토어를 거치지 않고도 최신 기능과 버그 수정을 빠르게 받을 수 있다.

**Why this priority**: 앱스토어 심사 없이 즉각적인 버그 수정과 기능 업데이트가 가능하여 사용자 경험 개선에 핵심적인 기능

**Independent Test**: 앱 실행 시 업데이트 확인 및 다운로드 동작을 확인하고, 다음 실행 시 새 버전이 적용되는지 검증

**Acceptance Scenarios**:

1. **Given** 앱이 실행되고 새로운 OTA 업데이트가 있을 때, **When** 앱이 포그라운드 상태일 때, **Then** 백그라운드에서 업데이트를 다운로드한다
2. **Given** OTA 업데이트 다운로드가 완료되었을 때, **When** 사용자가 앱을 다시 실행하면, **Then** 새로운 버전이 자동으로 적용된다
3. **Given** 네트워크가 불안정할 때, **When** 업데이트 다운로드가 실패하면, **Then** 기존 앱 버전으로 정상 동작하고 다음 실행 시 재시도한다

---

### User Story 2 - 푸시 알림 수신 (Priority: P1)

사용자가 앱을 설치하고 알림 권한을 허용하면, 서버에서 보내는 마케팅 알림, 주문 상태 알림, 프로모션 정보 등을 실시간으로 수신할 수 있다.

**Why this priority**: 사용자 재방문율과 전환율을 높이는 핵심 마케팅/커뮤니케이션 채널

**Independent Test**: 푸시 알림을 전송하고 디바이스에서 정상 수신되는지 확인

**Acceptance Scenarios**:

1. **Given** 앱을 처음 설치한 사용자가 있을 때, **When** 앱을 실행하면, **Then** 푸시 알림 권한 요청 팝업이 표시된다
2. **Given** 알림 권한을 허용한 사용자가 있을 때, **When** 서버에서 푸시 알림을 전송하면, **Then** 사용자 디바이스에 알림이 표시된다
3. **Given** 알림 권한을 거부한 사용자가 있을 때, **When** 앱을 사용하면, **Then** 앱은 정상적으로 동작하고 알림 기능만 비활성화된다

---

### User Story 3 - 푸시 알림 탭하여 앱 이동 (Priority: P2)

사용자가 수신한 푸시 알림을 탭하면, 해당 알림과 관련된 상세 페이지(상품 상세, 주문 상세 등)로 직접 이동할 수 있다.

**Why this priority**: 푸시 알림의 마케팅 효과를 극대화하는 딥링크 기능

**Independent Test**: 특정 상품 ID가 포함된 푸시 알림을 탭하면 해당 상품 상세 페이지로 이동하는지 확인

**Acceptance Scenarios**:

1. **Given** 상품 프로모션 푸시 알림을 수신했을 때, **When** 알림을 탭하면, **Then** 해당 상품 상세 페이지로 이동한다
2. **Given** 앱이 종료된 상태에서 푸시 알림을 수신했을 때, **When** 알림을 탭하면, **Then** 앱이 실행되며 해당 페이지로 이동한다
3. **Given** 앱이 포그라운드 상태에서 푸시 알림을 수신했을 때, **When** 인앱 알림 배너를 탭하면, **Then** 해당 페이지로 이동한다

---

### User Story 4 - 푸시 토큰 서버 등록 (Priority: P2)

사용자가 알림 권한을 허용하면, 해당 디바이스의 푸시 토큰이 서버에 등록되어 서버에서 특정 사용자에게 푸시 알림을 보낼 수 있다.

**Why this priority**: 타겟팅 푸시 알림을 위한 필수 인프라

**Independent Test**: 알림 권한 허용 후 서버 API에 푸시 토큰이 정상 등록되는지 확인

**Acceptance Scenarios**:

1. **Given** 사용자가 알림 권한을 허용했을 때, **When** 푸시 토큰이 생성되면, **Then** 서버에 토큰이 등록된다
2. **Given** 푸시 토큰이 갱신되었을 때, **When** 앱이 실행되면, **Then** 서버에 새 토큰으로 업데이트된다
3. **Given** 로그인 상태가 변경되었을 때, **When** 사용자가 로그인/로그아웃하면, **Then** 토큰과 사용자 ID 매핑이 업데이트된다

---

### User Story 5 - 중요 업데이트 강제 적용 (Priority: P3)

긴급 보안 패치나 중요 버그 수정이 있을 때, 관리자가 강제 업데이트를 배포하면 사용자에게 즉시 업데이트가 적용된다.

**Why this priority**: 긴급 상황 대응을 위한 선택적 기능

**Independent Test**: 강제 업데이트 배포 후 앱 재시작 없이 즉시 적용되는지 확인

**Acceptance Scenarios**:

1. **Given** 강제 업데이트가 배포되었을 때, **When** 사용자가 앱을 사용 중이면, **Then** 업데이트 알림이 표시되고 앱이 재시작된다
2. **Given** 강제 업데이트 적용 후, **When** 사용자가 앱을 사용하면, **Then** 최신 버전으로 동작한다

---

### Edge Cases

- 네트워크 연결이 없을 때 OTA 업데이트 및 푸시 토큰 등록은 어떻게 처리되는가? → 다음 네트워크 연결 시 재시도
- 푸시 알림 딥링크의 대상 페이지가 존재하지 않으면? → 홈 화면으로 fallback
- OTA 업데이트 다운로드 중 앱이 종료되면? → 다음 실행 시 처음부터 다시 다운로드
- iOS에서 알림 권한을 "나중에"로 선택하면? → 다음 앱 실행 시 다시 요청하지 않고, 설정에서 수동 변경 안내
- 업데이트 적용 후 롤백이 필요하면? → 관리자가 이전 버전을 다시 배포

## Requirements *(mandatory)*

### Functional Requirements

**OTA 업데이트 (EAS Update)**

- **FR-001**: 시스템은 앱 실행 시 새로운 OTA 업데이트 존재 여부를 확인해야 한다
- **FR-002**: 시스템은 업데이트를 백그라운드에서 다운로드하고 다음 앱 실행 시 적용해야 한다
- **FR-003**: 시스템은 강제 업데이트 옵션을 지원하여 즉시 적용이 가능해야 한다
- **FR-004**: 시스템은 업데이트 실패 시 기존 버전으로 정상 동작해야 한다 (롤백)
- **FR-005**: 시스템은 업데이트 다운로드 진행 상태를 추적할 수 있어야 한다

**푸시 알림**

- **FR-006**: 시스템은 앱 첫 실행 시 푸시 알림 권한을 요청해야 한다
- **FR-007**: 시스템은 푸시 토큰을 생성하고 서버에 등록해야 한다
- **FR-008**: 시스템은 포그라운드, 백그라운드, 종료 상태에서 푸시 알림을 수신해야 한다
- **FR-009**: 시스템은 푸시 알림 탭 시 지정된 딥링크로 이동해야 한다
- **FR-010**: 시스템은 토큰 갱신 시 서버에 자동으로 업데이트해야 한다
- **FR-011**: 시스템은 사용자 로그인 상태와 푸시 토큰을 연동해야 한다

### Key Entities

- **OTA Update**: 업데이트 ID, 버전, 다운로드 상태, 강제 여부, 생성일
- **Push Token**: 디바이스 토큰, 플랫폼(iOS/Android), 사용자 ID, 등록일, 갱신일
- **Push Notification**: 알림 ID, 제목, 본문, 딥링크 URL, 전송 대상, 전송 시간

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: OTA 업데이트 다운로드 완료율 95% 이상 (네트워크 정상 환경 기준)
- **SC-002**: 업데이트 배포 후 24시간 내 활성 사용자 80% 이상이 새 버전 적용
- **SC-003**: 푸시 알림 권한 수락률 60% 이상
- **SC-004**: 푸시 알림 수신 후 앱 오픈 전환율 측정 가능
- **SC-005**: 푸시 알림 탭 시 3초 이내 딥링크 대상 페이지 도달
- **SC-006**: 업데이트 적용 후 앱 크래시율 증가 없음 (기존 대비 ±0.1%)

## Assumptions

- Expo의 EAS Update 서비스를 사용한다 (Microsoft CodePush가 아닌 Expo 네이티브 솔루션)
- Expo의 expo-notifications 패키지를 사용한다
- 푸시 알림 서버 인프라(FCM, APNs)는 백엔드 팀에서 구축/관리한다
- 푸시 토큰 등록 API는 백엔드에서 제공한다
- 기존 authStore의 로그인 상태와 연동한다
- WebView 내부 콘텐츠가 아닌 네이티브 앱 코드만 OTA 업데이트 대상이다
